# 能力训练平台 · Training

> 钟锐的能力训练平台 — 面向 **策略运营 / 用户增长** 方向，依据大厂公开招聘要求反推能力模型，逐项设计可训练模块。
> 纯前端实现（sql.js 在浏览器内跑真实 SQLite），**零服务器、零成本**，可部署 GitHub Pages。

线上地址（部署后）：https://zr-president.github.io/training/

## 怎么用（3 步）

1. **先自评** → 打开「能力雷达」，给 10 项能力打分，立刻知道起点与最大短板在哪
2. **按天练** → 打开「30 天训练计划」，每天 40-60 分钟，做完打勾；不用纠结先学什么
3. **验证产出** → 用判读题、PRD 工坊、面试题库检验 —— **能讲清楚才算真会**

## 两个目标求职方向

| 方向 | 需要的能力 | 核心门槛 |
|------|-----------|---------|
| **策略运营 / 用户增长** | SQL + 数据分析与拆解 + 指标体系 + 实验分析 + 量化拆解 | SQL 必须熟练（面试会现场出题），且要能把数据讲成业务结论 |
| **AI 产品经理 (AI PM)** | AI 适用性判断 + 方案选型 + 验收标准 + PRD 表达 + 成本测算 | 能判断「什么该用 AI、什么不该」，并能写清「出问题怎么办」 |

## 30 天训练计划（4 个阶段）

| 阶段 | 天数 | 目标 |
|------|------|------|
| 打地基 | Day 1-7 | 能读懂数据集、写出基础 SQL、跑通 Python 环境 |
| 核心数据能力 | Day 8-14 | 掌握多表关联、窗口函数、留存与漏斗的标准写法 |
| 业务分析能力 | Day 15-21 | 能从业务问题出发独立产出分析结论 |
| 产品与实战 | Day 22-30 | 补齐产品能力、准备面试、做出可展示的项目 |

每天 2-4 个任务、40-60 分钟，任务都带「去练 →」直达对应模块；点「开始计划」记录 Day 1 日期后，会自动显示「今天是第几天」并支持一键跳转。

### 各模块定位

| 模块 | 形式 | 练什么 |
|------|------|--------|
| SQL 训练场 | 按需求写 SQL，自动判分 | SQL 语法与写法（硬门槛） |
| 数据集实验室 | 给业务问题，自己找答案 | **分析思路**：拆哪个维度、用什么口径 |
| 指标设计工坊 | 从候选指标里挑出该纳入的，自动判分 | **辨别虚荣指标/存量指标/不可归因指标** |
| 实验分析训练 | 给实验数据判断能否上线，自动判分 | **实验判读**：peeking、护栏指标、分层异质性、分流质量、指标冲突 |
| Case 拆解训练 | 给现象，自己列假设→设计验证→给方案 | **结构化拆解**（字节 JD 明确要求的"case 拆解"） |
| AI Agent 实操 | 判读设计 + 算清提效 + 动手任务 + 模板 | **AI 如何提升运营效率**（JD 第 2 条硬性要求） |
| 能力雷达 | 9 维自评 → 对比岗位要求 → 差距清单 | **自我定位**：先补哪个短板收益最高 |
| Python 数据分析案例 | 教学为主：可复制代码 + 真实运行结果 | **pandas 常用套路**（读取/清洗/聚合/留存/统计） |
| AI 产品经理 | 判读题 + PRD 工坊 + 能力迁移对照 | **运营转 AI PM**：AI 适用性、优先级、验收标准、技术选型、成本测算、PRD 表达 |

**各模块内容量**：SQL 31 题（L1-L5 分布 5/8/7/6/5）· 实验室 12 题含 30 条参考 SQL · 指标工坊 8 题含 70 个候选指标 · 实验分析 9 题含 36 个选项 · Case 拆解 7 题含 34 个原因假设 · Agent 4 道判读 + 4 个实操任务 + 3 份模板 · **Python 案例 16 个（5 个分组）+ 6 道代码实例题** · **AI 产品经理 10 道判读 + 4 套 PRD + 8 维能力对照** · 能力雷达 9 维（5 项硬性要求）。

### Python 数据分析案例（教学模块）

**定位是教学，不要求在线运行**——把代码复制到本地 Jupyter / VS Code 跑即可。

| 分组 | 案例 |
|------|------|
| 数据读取与体检 | 读取 + 体检三件套 / 缺失值与重复值 / **Excel 多 sheet 读写** |
| 数据清洗与加工 | 日期解析与类型转换 / 条件筛选与向量化新增列 / 分箱与用户分层（cut vs qcut）/ **长宽表转换 melt 与 pivot** / **分层抽样** |
| 聚合与合并 | groupby 多指标 agg / 多表 merge 行数校验 / 透视表 pivot_table / 组内占比 transform / **表格拼接 concat** |
| 时间序列与留存 | **时间重采样与移动平均** / 按月聚合与环比 / **次日留存率 cohort 标准写法** / 漏斗转化率 |
| 排名与统计 | 分组 TopN 与 rank / 相关性分析 / 卡方检验 / 结果导出 / **给图表准备数据** |

每个案例包含：**场景 → 代码（语法高亮 + 一键复制）→ 真实运行结果 → 逐点讲解 → 常见坑**。

**面试常考标签**：每个案例都标注了重要程度（`🔥 面试必考` / `面试常考` / `A/B 必考` / `最容易错` / `基本功`），侧边列表里 🔥 开头的是必须掌握的。

> ⚠️ **运行结果是用真实 pandas 2.2 跑出来并自动写入数据的**（生成器 `tools/gen_pycases.py` 会逐条执行代码并捕获 stdout），所以页面上的输出与代码严格一致，不是手写示意。

另有 **6 道代码实例题**（纯 Python 留存 / pandas 留存 / DAU / 卡方检验 / LTV-CAC / 相关性），每题给出任务、起始模板、**参考解**与**真实运行得到的预期结果**，可自己写完再对照。

### AI 产品经理模块（运营转型专项）

针对「从运营转 AI 产品经理」的实际情况设计，分三个 Tab：

1. **能力对照**：8 维能力逐项对照「你的运营积累 / AI PM 要求 / 可直接迁移 or 需重点补 / 怎么讲怎么补」，并给出面试话术建议
2. **判读题（10 题，自动判分）**：AI 适用性判断、RICE 优先级、AI 验收标准、RAG/微调/Prompt 选型、幻觉治理、token 成本测算、PRD 结构、AI 功能指标、转型路径、向上沟通
3. **面试题库（18 题，6 个分类，高频 10 题）**：开场与转型 / 产品与需求 / AI 技术理解 / 数据与实验 / 项目与协作 / 反问环节 —— 每题给出「考察意图 → 回答框架 → 参考要点 → 加分说法 / 减分说法」，可标记"已准备"追踪进度
4. **PRD 工坊（4 套，开放题）**：AI 周报 PRD / AI 客服 PRD（含幻觉兜底）/ 模型选型与成本测算 / 灰度与评测方案 —— 每套都有分模块填写区 + 参考 PRD + 常见错误

> 核心判断：**能用确定性代码解决的事，绝不要用模型**；AI 功能 PRD 的价值集中在「不做什么」和「出问题怎么办」。

### 提效计算器的设计要点

它不是为了算出一个好看的数，而是为了**暴露常见的高估**：多数人只算「人工耗时 − Agent 生成耗时」，忽略了**审核时间**与**维护调试时间**。计算器会同时给出「错误算法」与「真实算法」的结果，并显示高估幅度——这个差距本身就是面试时的专业度体现。

## 训练数据集

场景：内容社区 App「增长实验室」，数据区间 2026-08-01 ~ 2026-09-10

| 表 | 说明 | 行数 |
|----|------|------|
| `users` | 注册日期 / 渠道 / 城市 / 年龄 / 性别 | 620 |
| `events` | login / post / like / comment / share | 5512 |
| `orders` | 金额 / 商品 | 148 |
| `channels` | 投放成本 / 渠道类型 | 6 |

**渠道差异化设计**（便于练习留存、ROI、LTV/CAC）：
- 朋友推荐 —— 留存最高、零成本（自然流量）
- 抖音 —— 量最大但留存最低、成本最高
- 微信 / 小红书 / B站 / 应用商店 —— 介于两者之间

数据集可用 `tools/gen_dataset.py` 重新生成（固定随机种子，结果可复现）。

## 技术说明

- **主题系统**：亮色为默认，支持**夜间模式**切换；提供 6 套主题色（靛蓝/深海蓝/墨绿金/玫瑰金/琥珀暖/石墨灰）
  - 与个人网站**共用** `localStorage` 键 `theme` / `themeColor` → 两站主题选择自动同步
  - 科技感通过渲染实现（渐变光晕 + 网格叠加 + 玻璃顶栏 + 模块配色 + 渐变标题），而非深色背景
  - 7 个模块各有独立配色（SQL 蓝 / 实验室 青 / 指标 紫 / 实验 橙 / Case 玫红 / Agent 绿 / 雷达 琥珀）
- **SQL 引擎**：`sql.js` 1.10.2（SQLite 的 WebAssembly 版），浏览器内执行真实 SQL
- **判分方式**：你的结果集与参考解结果集对比
  - 含 `ORDER BY` 的题按顺序比对；否则按**无序多重集**比对（不对写法做限制，思路对就给过）
  - 数字容差 3 位小数；`'3'` 与 `3` 视为相等；列名可不同（只看列数）
- **体积策略**：数据集 472KB **懒加载**——只有进入 SQL 模块才下载；首页只加载 0.9KB 元数据
- **进度存储**：`localStorage`（`tp_progress_v1`），只存在你自己的浏览器
- **自检**：访问 `index.html?selftest=1` 会跑通全部参考解并输出 `SELFTEST_RESULT n/20`
