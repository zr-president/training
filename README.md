# 能力训练平台 · Training

> 钟锐的能力训练平台 — 面向 **策略运营 / 用户增长** 方向，依据大厂公开招聘要求反推能力模型，逐项设计可训练模块。
> 纯前端实现（sql.js 在浏览器内跑真实 SQLite），**零服务器、零成本**，可部署 GitHub Pages。

线上地址（部署后）：https://zr-president.github.io/training/

---

## 为什么做这个

个人网站解决的是「**我今天该关注什么**」（信息中枢），这个平台解决的是「**我这项能力到底行不行**」（刻意练习）。

依据**字节跳动策略运营岗真实 JD** 反推 9 维能力模型：

| # | 能力 | JD 依据 | 可训练性 |
|---|------|---------|---------|
| 1 | SQL 数据提取 | 熟练使用SQL（硬性） | ★★★★★ |
| 2 | 数据分析与问题拆解 | 较强的数据分析与问题拆解能力（硬性） | ★★★★★ |
| 3 | AI/LLM/Agent 理解 | 对AI产品/LLM/Agent/Workflow有较强兴趣（硬性） | ★★★★★ |
| 4 | AI 提升运营效率 | AI与自动化工具落地应用（硬性） | ★★★★☆ |
| 5 | 量化拆解·系统思考 | 复杂业务问题量化拆解和系统化思考（硬性） | ★★★★☆ |
| 6 | 实验分析 (A/B) | 有实验分析经验加分 | ★★★★☆ |
| 7 | 指标体系设计 | 有指标体系设计经验加分 | ★★★★☆ |
| 8 | 运营SOP/工作流设计 | 运营SOP优化、工作流建设（职责） | ★★★☆☆ |
| 9 | 方法论沉淀 | 沉淀方法论与最佳实践（职责） | ★★★☆☆ |

### 各模块定位

| 模块 | 形式 | 练什么 |
|------|------|--------|
| SQL 训练场 | 按需求写 SQL，自动判分 | SQL 语法与写法（硬门槛） |
| 数据集实验室 | 给业务问题，自己找答案 | **分析思路**：拆哪个维度、用什么口径 |
| 指标设计工坊 | 从候选指标里挑出该纳入的，自动判分 | **辨别虚荣指标/存量指标/不可归因指标** |
| 实验分析训练 | 给实验数据判断能否上线，自动判分 | **实验判读**：peeking、护栏指标、分层异质性、统计≠业务显著、AA 校验 |
| Case 拆解训练 | 给现象，自己列假设→设计验证→给方案 | **结构化拆解**（字节 JD 明确要求的"case 拆解"） |
| AI Agent 实操 | 判读设计 + 算清提效 + 动手任务 + 模板 | **AI 如何提升运营效率**（JD 第 2 条硬性要求） |
| 能力雷达 | 9 维自评 → 对比岗位要求 → 差距清单 | **自我定位**：先补哪个短板收益最高 |

**各模块内容量**：SQL 20 题（L1-L5 分布 5/5/4/3/3）· 实验室 8 题含 19 条参考 SQL · 指标工坊 6 题含 54 个候选指标 · 实验分析 6 题含 24 个选项 · Case 拆解 5 题含 25 个原因假设 · Agent 4 道判读 + 4 个实操任务 + 3 份模板 · 能力雷达 9 维（5 项硬性要求）。

### 提效计算器的设计要点

它不是为了算出一个好看的数，而是为了**暴露常见的高估**：多数人只算「人工耗时 − Agent 生成耗时」，忽略了**审核时间**与**维护调试时间**。计算器会同时给出「错误算法」与「真实算法」的结果，并显示高估幅度——这个差距本身就是面试时的专业度体现。

## 训练数据集

场景：内容社区 App「增长实验室」，数据区间 2026-08-01 ~ 2026-09-10

| 表 | 说明 | 行数 |
|----|------|------|
| `users` | 注册日期 / 渠道 / 城市 / 年龄 / 性别 | 620 |
| `events` | login / post / like / comment / share | 5512 |
| `orders` | 金额 / 商品 | 148 |
| `channels` | 投放成本 / 渠道类型 | 6 |

**渠道差异化设计**（便于练习留存、ROI、LTV/CAC）：
- 朋友推荐 —— 留存最高、零成本（自然流量）
- 抖音 —— 量最大但留存最低、成本最高
- 微信 / 小红书 / B站 / 应用商店 —— 介于两者之间

数据集可用 `tools/gen_dataset.py` 重新生成（固定随机种子，结果可复现）。

## 技术说明

- **主题系统**：亮色为默认，支持**夜间模式**切换；提供 6 套主题色（靛蓝/深海蓝/墨绿金/玫瑰金/琥珀暖/石墨灰）
  - 与个人网站**共用** `localStorage` 键 `theme` / `themeColor` → 两站主题选择自动同步
  - 科技感通过渲染实现（渐变光晕 + 网格叠加 + 玻璃顶栏 + 模块配色 + 渐变标题），而非深色背景
  - 7 个模块各有独立配色（SQL 蓝 / 实验室 青 / 指标 紫 / 实验 橙 / Case 玫红 / Agent 绿 / 雷达 琥珀）
- **SQL 引擎**：`sql.js` 1.10.2（SQLite 的 WebAssembly 版），浏览器内执行真实 SQL
- **判分方式**：你的结果集与参考解结果集对比
  - 含 `ORDER BY` 的题按顺序比对；否则按**无序多重集**比对（不对写法做限制，思路对就给过）
  - 数字容差 3 位小数；`'3'` 与 `3` 视为相等；列名可不同（只看列数）
- **体积策略**：数据集 472KB **懒加载**——只有进入 SQL 模块才下载；首页只加载 0.9KB 元数据
- **进度存储**：`localStorage`（`tp_progress_v1`），只存在你自己的浏览器
- **自检**：访问 `index.html?selftest=1` 会跑通全部参考解并输出 `SELFTEST_RESULT n/20`

## 本地运行

```bash
cd 钟锐的训练场
python -m http.server 8924
# 打开 http://127.0.0.1:8924
```

> 必须用 HTTP 服务打开（`file://` 下 sql.js 的 WASM 可能受同源策略限制）。
